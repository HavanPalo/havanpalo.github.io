DNV-RU-SHIP Pt.6 Ch.11 · Edition July 2025

D-INF Notation:

Standardize how your vessel talks to shore.

D-INF is DNV's additional class notation for data collection infrastructure — reliable, secure, verifiable data from sensor to remote server. It says nothing about the sensors themselves. It governs everything after them.

Section 1.5 — Table 1

Three ways to hold the notation

Every D-INF certificate is built one of three ways — from a fully custom pipeline to a fully standardized one.

D-INF · NO QUALIFIER

Essential

A predefined set of tags from one specific source system, at a specific rate, to one specific target. Fully customized.

  • No vessel server required
  • Proprietary protocols throughout
  • Built around a single use case
Maps to CG-0564 variant 0
D-INF(G)

Generic

A flexible set of tags from a range of source systems. Standardized requirements, but a proprietary interface.

  • Vessel server required
  • No defined external interface
  • 30-day onboard buffer minimum
Maps to CG-0564 variant 1
D-INF(S)

Standardized

Same flexible collection as Generic, built to a published standard so any conformant client can talk to it.

  • ISO 19847 / 19848, or OPC UA + IEC 61162-450
  • Vessel server recommended in its own DMZ
Maps to CG-0564 variant 2 or 3
Section 2 — Requirements

The three certifiable components

Switch the qualifier above — components that don't apply to your selection fade out.

Vessel server

Product Certificate

Collects data through one or more interfaces, buffers it, and serves it to local clients. Required for Generic and Standardized; skipped under Essential.

Data relay component

Product Certificate

The mandatory intermediary for every qualifier. Priority management for at least three traffic levels, plus an API for status, alerts, and transfer-delay logs.

Remote data server

TA or case-by-case

Receives data from potentially many vessel servers, persists at least three years of history, and serves it to remote consumers.

Section 1.8 & Section 3

Getting — and keeping — the notation

Two activities are mandatory. A third exists, but only kicks in once the data is put to use elsewhere in class.

01 · Mandatory

Document it

Topology diagrams, function descriptions, inventory lists, bandwidth budgets, change-handling procedures — per component or as one end-to-end package.

02 · Mandatory

Survey & test

An approved test programme, witnessed by a surveyor: functions, security, UPS capacity, connected sources, clock sync.

Result

D-INF assigned

Retained through successful annual surveys. Data quality management and CSMS are not required at this point.

03 · Conditional

Data quality & CSMS

Mandatory only once the data is used for another notation, an in-operation notation, or another class methodology.

optional until triggered
